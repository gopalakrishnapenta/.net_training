🚀 Setup & Getting Started

Prerequisites

  • .NET 10.0 SDK or later - Download
  • Visual Studio Code or Visual Studio 2022 (recommended)
  • Git for version control

Installation Steps

  1. Clone or download the repository:
    git clone <repository-url>
  2. Navigate to the project directory:
    cd Capgemini
  3. Verify .NET installation:
    dotnet --version
  4. Open in IDE:

    Using Visual Studio:

    start Asg.sln

    Or open Asg.sln directly from File → Open

💡 Tip: VS Code with C# DevKit extension is lightweight and perfect for this repository. Install the extension and open the workspace folder.

⚙️ Build & Run Commands

Building the Solution

Build all projects:

dotnet build Asg.sln

Build a specific project:

dotnet build "ConditionalStatements/lab1.csproj"

Running Projects

Run a specific exercise:

dotnet run --project "LoopsAndJumpStatements/PrimeNumber/PrimeNumber.csproj"

Run with project context (from folder):

cd LoopsAndJumpStatements/PrimeNumber dotnet run

Example: Running Common Exercises

Exercise Command
Prime Number dotnet run --project LoopsAndJumpStatements/PrimeNumber/PrimeNumber.csproj
Fibonacci Series dotnet run --project LoopsAndJumpStatements/FibonacciSeries/FibonacciSeries.csproj
Simple Calculator dotnet run --project ConditionalStatements/SimpleCalculator/SimpleCalculator.csproj
Leap Year Checker dotnet run --project ConditionalStatements/LeapYearChecker/LeapYearChecker.csproj

Other Useful Commands

Clean build artifacts:

dotnet clean Asg.sln

Restore dependencies:

dotnet restore Asg.sln

List all projects in solution:

dotnet sln Asg.sln list
✓ Pro Tip: Set your working directory to a specific project folder, then use dotnet run without the --project parameter for convenience.

📋 Project Conventions

Naming Conventions

  • Folder names: PascalCase (e.g., PrimeNumber, FibonacciSeries)
  • Project files: Match folder name (e.g., PrimeNumber.csproj)
  • Classes: PascalCase (e.g., public class Calculator { })
  • Methods: PascalCase (e.g., public void CalculateResult())
  • Variables: camelCase (e.g., int userInput;)

File Structure

Standard project structure for each exercise:

ExerciseName/
├── ExerciseName.csproj
├── Program.cs                 # Contains Main() entry point
└── [Optional] HelperClass.cs  # Additional classes if needed

Program Entry Point

All projects use the top-level statements pattern (modern C# default):

// Program.cs
Console.WriteLine("Enter a number: ");
string input = Console.ReadLine();

if (int.TryParse(input, out int number))
{
    // Process the number
    Console.WriteLine($"You entered: {number}");
}
else
{
    Console.WriteLine("Invalid input!");
}

Input/Output Standards

  • Use Console.ReadLine() for user input
  • Use int.TryParse(), double.TryParse() for safe parsing
  • Use Console.WriteLine() for output
  • Provide clear, user-friendly prompts
  • Handle invalid input gracefully
ℹ️ Framework Target: All projects target <TargetFramework>net10.0</TargetFramework>. This is non-negotiable unless explicitly requested.

📖 Development Guidelines

When Adding New Exercises

  1. Create a new folder with a clear, descriptive name (PascalCase)
  2. Create a matching .csproj file with SDK-style settings
  3. Add a Program.cs with Main entry point
  4. Ensure the project targets net10.0
  5. Test the project with dotnet run
  6. Add the project to Asg.sln if needed: dotnet sln Asg.sln add "path/to/Project.csproj"

Project Modification Rules

  • ✓ DO: Keep modifications local to a single project
  • ✓ DO: Run dotnet build Asg.sln after changes
  • ✓ DO: Test individual exercises thoroughly
  • ✓ DO: Follow existing naming conventions
  • ✗ DON'T: Introduce external NuGet packages without approval
  • ✗ DON'T: Refactor multiple projects simultaneously
  • ✗ DON'T: Modify solution-level files without explicit approval
  • ✗ DON'T: Add heavy frameworks or databases

Code Quality Standards

  • Use meaningful variable and method names
  • Add comments for complex logic
  • Validate user input properly
  • Handle edge cases (division by zero, negative numbers, etc.)
  • Keep projects focused on a single concept
  • Test with various inputs including edge cases

Common Improvements

  • Fix typos in console messages
  • Improve input validation with TryParse
  • Clarify user-facing prompts and messages
  • Add error handling for invalid operations
  • Enhance code readability and documentation
⚠️ Remember: These are educational exercises designed to teach C# concepts. Keep projects simple and focused on demonstrating specific language features.

🔧 Troubleshooting

Common Issues & Solutions

Issue: .NET SDK not found

Solution: Verify .NET is installed correctly:

dotnet --version

If not installed, download from dotnet.microsoft.com

Issue: Project won't build

Solution: Try cleaning and rebuilding:

dotnet clean Asg.sln dotnet build Asg.sln

Issue: Wrong .NET version required

Solution: Check the project's .csproj file and ensure it targets net10.0. Update if necessary with proper approval.

Issue: Cannot find project file

Solution: Verify the path is correct. Projects must exist in subdirectories matching the folder structure.

dir /s *.csproj # Windows find . -name "*.csproj" # Linux/Mac
